## 画面

- ヘッダー（常時表示）：左に日付、中央に「ホーム」、右に「車両」。パステル調のグラデーション。表示中の画面側のボタンが色付き。
- 起動：その日の最初は「車両」、2回目以降は「ホーム」。
- ホーム：上から、客先名リストの状態バー（取り込む／追加・更新／管理）、訪問先の入力と50音、「開始」、「日報をメール送信」、削除ボタン2つ、TODOリスト（見出しの右に「消す=コピー可」。空なら非表示）、訪問履歴（見出しの右に「✓ ToDoリストへ追加」）。
- 訪問入力・編集：訪問先（開始後は固定）、開始時刻（修正できる）、面談者と敬称、内容区分の8ボタン、内容、特記事項、「記録終了」と小さな「削除」（幅は4対1）、TODOリスト。編集のときは「保存」と「削除」で、開始・終了時刻を直せる。
- 車両：出発／帰社のスイッチ、走行距離（右横に給油量）、ダイヤル（左）と記録ボタン（右）、本日の走行距離、TODOリスト（手入力の追加欄あり）。
- 見た目：パステル調、フォントは BIZ UDPGothic、行数を少なく、ボタンは押しやすく。

## 動作のルール

- 連番：訪問ごとの「No.」。1日ごとにリセット。
- 敬称：初期値「さん」。候補は社長・工場長・専務・常務・部長・課長。自由入力もできる（自作のドロップダウン。ブラウザ標準の候補表示はiPhoneで動かなかった）。
- 内容区分：引取・配達・注文・営業・周知文書・集金・苦情・新規の8ボタン（4列×2行）。押すと内容欄に区分名が追記される入力補助。何度でも押せる。区分は別の項目として保存しない。
- 位置情報：開始・終了・出発・帰社の時点で裏で取得。画面には出さず、スマホ内の記録に保存し、日報メールに載せる。
- 車両：出発時の走行距離は、直近の帰社時の値を自動で入れる（修正できる）。帰社時の初期値は出発時の値。ダイヤルは、中心に近いほど細かく、外側ほど大きく変わる（`kmPerDegree = min(3, 半径/250)`）。出発を記録すると、自動で帰社側に切り替わる。帰社を記録すると、ホームに戻る。帰社でメールは自動で作らない（一度そうしたが撤回）。時刻は走行距離の行の右端に出す。
- TODO：追加は、(1) 訪問履歴の内容の行のチェック、(2) 車両画面で手入力。ホーム・訪問入力・車両の3か所に同じリスト。1行で「月/日　客先名　内容」。チェックすると、「客先名　内容(9/2分)」をコピーして完了にし、リストから消す。元の内容の行は、赤い取り消し線と、赤字の「(10/1 済)」になる。右端の「≡」を押したままドラッグして並べ替える（`order` に保存）。完了後もデータに残る。
- 訪問履歴：全データを削除するまで、全日を日付ごとに新しい順で表示。各カードに「編集」「削除」。
- 削除ボタン：「全データを削除」（訪問・車両・TODOを削除）と「TODOを残して削除」（訪問・車両だけ削除）。どちらも確認が出る。客先名リストは、どちらでも消えない（「管理」から消す）。
- バックアップ保存・復元は、一度作ったが、不要として削除した。

## 客先名リスト

- 流れ：CSV（営業所、顧客コード、客先名、ふりがな）→ PCのツールで担当ごとの暗号化ファイル（.enc）→ 配る → アプリで営業所キーを入れて取り込む。
- 配る方法：「ファイルから取り込む」（OneDriveやメールで受け取ったファイルを選ぶ。通信なし。主な方法）と、「ネットから取得」（サーバーの `master/ID.enc`。残してある）。
- 暗号：AES-256-GCM。キーから PBKDF2-SHA256（60万回）で作り、HKDFで暗号鍵とファイルIDに分ける。キーは、全角→半角、大文字化、空白・ハイフン・長音記号を除いて整える。16文字以上。ツールの自動生成は20文字。営業所キーはスマホに保存しない。
- 複数の担当：取り込むたびに追加。同じ担当は更新（置き換え）。保存は `customerLists`。「管理」で担当ごとに消せる。
- 50音：すべてのリストを合わせて1つの「あ か さ た な は ま や ら わ 他」で選ぶ。顧客コードが同じ客先は1件にまとめる（新しい更新を優先）。同じ名前で顧客コードが違う客先は、担当名を小さく添える。
- 顧客コード：リストから選んだとき、または手入力の名前がリストの1件と完全に一致したときに、裏で付ける。画面には出さない。
- 抽出元：顧客コード＝会社コード（担当コード表が基準）。客先名＝Accessの顧客名称（会社名簿の会社名）。ふりがな＝略名カナ（会社名簿のフリガナから会社種別語を除いて作る）。営業所（担当）＝担当コード表の担当コードを「担当コード名称表」で名前にしたもの（地名と人名が混在）。
- 会社語の除去：ツールが、客先名から「株式会社」などを除く（34語。画面で編集できる）。空になる名前と、同じ名前になる客先は、元のまま。
- 客先名は、法人名・屋号だけ。個人のお客様の氏名は含まない。利用者は11〜50人。会社はMicrosoft 365（OneDriveは可、SharePointは未加入）。OneDriveはHTMLを表示できないので、アプリ本体は置けない。

## 日報メール

- 「日報をメール送信」で、メールアプリを開く（宛先は空欄、件名「営業日報 日付」）。
- 全データを削除するまでの全期間。古い日から順。訪問も車両の記録もない日は載せない。
- 日ごとの並び：「日付：」→【車両情報】（出発時走行距離、出発時刻、帰社時走行距離、帰社時刻、給油量、出発時位置、帰社時位置）→【TODOリスト】（今日の日付の日だけ）→【訪問先 N】（訪問先、顧客コード、時間、面談者、内容、特記事項、開始位置、終了位置）。
- TODOリストは1つにまとめて連番。「1. 10/4　客先名　内容(未対応)」「2. 10/2　客先名　内容(10/4 済)」。未対応（並べ替えた順）の後に対応済み（これまで分すべて）。
- 位置は「緯度,経度」（小数6桁）。過去の日で出発・帰社の記録がない日は、走行距離と位置を空欄にする。
- 新しい行は、既存の行の並びを変えず、ブロックの末尾に足す（受け取り側の取り込みのため）。
- 約5万文字を超えると、本文をコピーして貼り付ける形に切り替える。

## 保存データ（localStorage）

- `meetingLogs`：訪問記録（date、number、target、customerCode、startTime、endTime、各位置、attendee、attendeeTitle、content、notes、createdAt）
- `dailyVehicleInfo`：日付ごとの departure と return（time、distance、location、lat、lng、fuel）、status
- `todoItems`：id、date、target、content、done、completedAt、source、sourceId、order、createdAt
- `customerLists`：担当名ごとに office、updated、items（c＝顧客コード、n＝客先名、k＝ふりがな）。旧 `customerMaster` は自動で引き継ぐ
- `appLastOpenDate`：最後に開いた日

## 利用者の好み

- 日本語だけで話す。専門用語を避け、順を追って短く説明する。
