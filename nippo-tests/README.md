# 営業日報アプリ 自動確認(疑似環境)

`container.js` の動きを、パソコンの中で確認する道具です。実機(iPhone)の見た目・指の操作・キーボードの動きは、確認できません。

## 使い方
1. このフォルダを、アプリのファイル(`container.js` など)のフォルダの中に置きます(フォルダ名は `nippo-tests` のままで構いません)。
   - `nippo-tests` フォルダの 1つ上に `container.js` があれば、それを自動で使います。
   - または、`container.js` を、このフォルダに入れます。
2. このフォルダで、`python run_tests.py` を実行します(Python 3 と Node.js が必要。jsdom は初回に自動で入ります)。
3. 最後に `ALL PASS` と出れば、すべて合格です。不合格の項目は、`FAIL` で始まる行で分かります。

## 中身
- `harness3.html` … 確認用の画面の元(index.html の作りを真似たもの。本物の index.html ではありません)
- `smoke7.js` … 確認の台本の元(古い部分)
- `extra_tests.js` … 確認の台本(新しい部分。機能ごとに、`// ---- 番号) ...` で区切っています)
- `build_tests.py`, `post_build*.py` … 上の2つを、現在の仕様に合わせて組み立てる順番どおりの書き換え(古い期待値を新しい仕様に直す役目)
- `run_tests.py` … 上の全部と、確認の実行をまとめたもの

## 注意
- `post_build*.py` は、仕様が変わるたびに、古い確認の文言を、決まった順番で書き換える作りです。新しい確認は、`extra_tests.js` の末尾に足すのが簡単です。古い確認の期待値を直すときは、`post_build7.py`(最後に実行)に書き足すと、他に影響しません。
- 本物の `index.html` とは、完全に同じではありません。`index.html` を変えたときは、`harness3.html`(と `post_build4.py` / `post_build6.py` が足している部品)を、合わせて直してください。
